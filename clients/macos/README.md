# macOS Client

Tier‑1 SwiftUI/AppKit 客户端。当前支持本地账号和 OIDC 登录、按控制面地址绑定的 Keychain Session、授权桌面列表、`vc-workspace://connect?vmid=<VMID>` App Link、启动与就绪等待，以及应用内 RDP 会话。旧 `vc-vdi://` 链接只作为迁移兼容入口读取。

## 原生数据面

客户端不启动 `sdl-freerdp` 或其他桌面应用。`EmbeddedRDP.swift` 从当前 `.app/Contents/Frameworks` 加载仓库内 C ABI Bridge（当前 ABI v5，应用和 Bridge 必须一起升级）；Bridge 使用 FreeRDP 原生 Mac Client 创建 `MRDPView`，SwiftUI 通过 `NSViewRepresentable` 把它放入当前窗口。连接、失败、断开、全屏与应用退出共享同一个生命周期。Bridge 在原生连接进入 Active 后补齐内嵌视图的 responder/剪贴板生命周期，并通过 RDP Display Control 把窗口内容区协商为 Guest 的真实桌面分辨率，而不是只放大旧画面。远端像素按 AppKit 内容区逻辑点乘当前 backing scale 计算，渲染倍率上限为 2×；Retina 使用 200% Desktop Scale，普通屏使用 100%。内嵌 NSView 始终保留父容器的逻辑点尺寸，不能被 FreeRDP 的远端像素尺寸覆盖。布局变化使用 180 ms 防抖；拖动结束、跨屏和全屏完成通知立即提交。协议未确认时先按 500 ms 间隔发送前四次，随后放缓到每 2 秒；总窗口 30 秒且最多 20 次，确认后停止。xrdp 首次登录可能在 Xorg 就绪前丢弃显示请求，该有界窗口允许它就绪后自动收敛；8 秒视觉回退不停止后续协商。

客户端声明 `vc-workspace-rdp.v1` 网关能力；只有控制面显式配置网关时才使用 `rdp-gateway` 描述符。该路径在应用内建立 TLS 1.3 WebSocket，并通过匿名 socket pair 将 RDP 流交给 Bridge，不开放本机监听端口。Guest TLS 保持端到端，严格按可信 Broker 的叶证书 SHA-256 验证，禁止 TOFU、跳转和直连回退；旧直连路径的行为未改变。异步建联可取消，迟到的旧会话会在注册前销毁并释放原 Connection，不能替换新尝试。协议、安全边界和未闭环的真实桌面验收见 [Session Gateway](../../docs/architecture/session-gateway.md)。

`ResizeWindow` 只表示缓冲区尺寸确认，不代表新画面已到达。最大化、拖动和全屏统一等待最新目标宽高的非空 `EndPaint`，期间只覆盖远程画布，顶部断开/全屏操作仍可用；不再使用固定 600 ms 延时猜测完成。超过 8 秒使用 Smart Sizing 兼容回退，并提供“重新调整画面”；迟到的目标画面到达后自动恢复正常状态。状态刷新不重新触发协商，避免无限重试。回退不等同于原生分辨率或相同清晰度，仍需对不支持 Display Control 的服务器单独验收。

会话外壳采用独立的 Pre-session 状态页。冷启动、恢复登录、登录提交和桌面加载使用居中品牌图、28 pt 阶段标题及非百分比活动条；用户点击桌面后，桌面库由“正在启动桌面”“正在准备桌面”“正在连接”依次接替。状态页保留桌面名、当前阶段、必要说明与取消操作，不显示计时器、网络档位或 Guest 实现。主动断开会先进入不可重复提交的“正在断开连接”，完成后停留在带“重新连接”和“返回桌面库”的恢复页；可恢复的传输错误先进入有界自动恢复，非重试错误或预算用尽后才显示失败恢复页，不把原始协议诊断铺到界面。原生 Bridge 只有在收到首个 RDP 绘制帧后才把会话报告为已连接，SwiftUI 再保留短暂的首帧稳定期，避免在尚无协议帧时切入空白画布；首个 RDP 帧不等同 Guest 已完成 OS 登录，冷登录另由有界显示协商处理。会话停止若未及时回调，客户端会在 8 秒后回收本地会话，避免界面永久停在断开中。

连接断开不等于 Guest 注销。Linux 版本化账号的普通断开只退役连接凭据，在原期限内保留桌面；平台注销或撤权才进入账号回收。客户端不从传输错误猜测桌面是否已结束：自动恢复不适用或用尽后，只读复核当前授权清单，桌面不可见时移除重试入口，登录过期时清理本地会话，复核失败时保持中性的恢复页。复核绑定服务器、登录 Token 和独立任务标识；重试、返回、注销或关窗会使旧结果失效，复核本身不签发新凭据。具体跨端验收边界见[项目状态](../../docs/plan/status.md)。

原生外观由 `WorkspaceStyle` 与 `WorkspaceActionStyle` 统一，登录、桌面库和连接页按职责拆分，不在背景铺装饰 Logo。系统明暗外观、按钮按压弹簧、字段焦点和 SF Symbol 阶段替换共用一套规则；活动时钟在窗口非活动或减少动态效果时暂停。桌面库支持即时搜索、⌘F 聚焦、Esc 清除，以及连接往返保留查询；注销清除查询。远程 NSView 不参与页面缩放或过渡动画，输入和连接时序不由动效驱动。详细规则见 [UI 设计语言](../../docs/design/ui.md)。

客户端是单窗口应用，不提供会产生重复会话状态的“新建窗口”或窗口标签页。应用菜单提供原生“关于”和“设置”，设置页可检查控制面连接且在登录期间锁定服务器地址；“连接”菜单随桌面库、建联、会话和断线恢复状态切换刷新、取消、断开、重连和返回动作。“显示”只保留原生全屏，“帮助”直接进入项目主页或 Issue 页面，不调用未配置的 macOS Help Book。全屏时显式隐藏 SwiftUI 系统窗口工具栏，退出时显式恢复可见；只设透明标题栏或隐藏系统按钮不足以移除 AppKit 独立的全屏工具栏窗口。

启动时的系统探测使用 8 秒请求超时，不等待网络恢复；不可达时仍显示可操作的登录/服务器设置。交互 Session 不启用 `waitsForConnectivity`，Guest 准备等长请求保留原有预算。设置检查结果在已登录和未登录时都显示；登录字段及服务器地址具有独立可访问名称。

Windows 可直接消费 RDP Desktop Scale。当前验收 VM 的 xrdp 动态显示通道不会把这个比例应用到 Xorg，因此客户端创建连接时通过受限请求头提交 100/200 两档 backing scale，控制面用固定 QGA 命令把 Debian XFCE 的 Xft DPI 同步为 96/192；模板只提供 96 DPI 安全默认值。该通道不接受任意命令或任意 DPI。已经建立的 Linux 会话从 1× 屏幕移到 2× 屏幕（或反向）时，分辨率仍会更新，但 Xft DPI 需要重新连接后同步；这是发布前需要补齐的多显示器边界。

受管 Linux 本地用户还通过无特权的 `internal/guestdesktop/session_layout.py` 同步面板行高、图标、光标和默认窗口装饰；记录上次比例，重复连接不重复放大，不重置用户面板组成或自定义主题。单屏 RDP 缩小时按工作区和实际窗口边框恢复越界普通窗口，不移动 Dock/桌面，不改变焦点、最小化、最大化或全屏状态。正式模板安装其依赖；旧模板需先补齐 `python3-gi gir1.2-gtk-3.0 wmctrl x11-utils`，注销 Guest 后的新会话才会启动辅助程序。不会在普通建联时运行 apt，也不强制结束保留中的应用。

密码直接写入当前进程的 FreeRDP settings，不进入进程参数、环境变量或文件。交互客户端请求网络自动检测、压缩、渐进式图形更新和显示协商，但是否生效取决于服务器；当前 xrdp 将 auto 视为 LAN，不能据此宣称已经实现动态码率适配。带宽参数不在普通用户的桌面库中展示。

明确的传输、连接或 DNS 故障由 Swift 控制面的连接流程恢复：120 秒内最多自动尝试两次，分别等待 2/5 秒，每次重新检查授权、策略和凭据；成功回到同一 OS 用户会话，不重放用户输入。恢复期间显示“正在恢复连接”并提供取消；超限或控制面请求失败后保留手动重试。证书/TLS、认证、服务器注销、未知错误和主动停止不自动重试。上游 Mac 事件循环没有实现自动重连，因此关闭其自动重连选项，避免两套恢复机制。原生会话必须先注册为 `activeSession` 再显式 `start()` 轮询，构造本身不能通知终止。连接任务和会话分别使用 UUID 绑定所有权，旧任务收尾、旧会话回调及迟到的首帧 UI 回调不能覆盖新连接；关闭窗口先解绑再停止，取消覆盖首帧稳定期和传输收尾瞬间，不能重新启动恢复。

诊断写入 macOS Unified Log 的 `ac.plz.vc-workspace` 子系统：只记录随机 attempt ID、阶段、耗时、FreeRDP 数值错误码及已知调用点。光标缓存诊断只接受固定格式和调用点，输出创建/写入/缺失的操作编号、槽编号及容量；不记录图像、桌面名、地址、用户名、密码或 Token，不直接显示协议错误文本。TCP 诊断的 `stage=1` 是立即连接的 Winsock 错误，`stage=2` 是异步 socket 的平台 `SO_ERROR`，`stage=3/code=0` 是等待超时；前两类错误码命名空间不同，不能混用解释。仅允许固定调用点、完整固定格式和 1–65535 的规范十进制错误码，原始错误文本不进入日志。Debug 包额外记录窗口几何，Release 不记录几何。可使用 `log show --last 10m --predicate 'subsystem == "ac.plz.vc-workspace"'` 排查。弱网故障注入的隔离与回滚方法见 [PVE 开发验收](../../docs/operations/pve-development.md#隔离的-rdp-弱网验收)。

## 构建

构建机需要 Swift 6、CMake 和 Ninja。脚本会自行构建固定的 OpenSSL LTS；最终用户不需要这些工具，也不需要 Homebrew、OpenSSL 或 FreeRDP。

```bash
./scripts/build-app.sh release
```

脚本下载 FreeRDP 3.31.0 与 OpenSSL 3.5.8 LTS 源码并校验 SHA-256，先幂等应用仓库内的 Mac 剪贴板和内嵌视图 resize 补丁，再面向 macOS 14 构建客户端所需的最小功能集，最后把 Bridge、FreeRDP、WinPR、OpenSSL、provider、证书对话框和第三方许可证写入并签名。补丁探针禁用正反向自动猜测，不能把尚未应用的补丁当作已安装。位图释放/发布与 AppKit 绘制在主线程串行执行；GDI resize/EndPaint 保留在协议线程，避免主队列自同步与 update lock 的线程归属错误。构建同时运行 `NativeRDP/tests/display-presentation.c` 的 24 条断言，覆盖旧帧、错高、空缓冲区、连续目标变化、8 秒回退、迟到新帧，以及冷登录协商退避、时钟边界和重试预算。

剪贴板定时器在读取本机内容（包括 change count）前检查连接策略及通道就绪条件，整个读取/发送操作与通道销毁通过同一取消对象串行化。定时器持有该对象，关闭后不访问原始上下文；主队列的旧通道清理按对象身份匹配，重复恢复不重复安装定时器。构建中的 `check-clipboard-read-policy.sh` 调用实际 FreeRDP 方法，以私有假剪贴板验证允许路径、八种拒绝状态、关闭后的无效上下文及恢复/替换时序，不读取系统剪贴板、不创建窗口或连接 Guest。这不是原生复制/粘贴的端到端证明；原生编辑响应、格式确认时序及实机验收状态统一见 [项目状态](../../docs/plan/status.md)。

远端文本写回使用每通道独立的 `VCWClipboardDelivery`，在销毁时同步关闭；排队块持有取消对象及远端版本，不捕获原始会话指针，新通知会使旧版本的排队写入失效。数据请求仅保留一个在途；等待期间的新通知合并为最新格式，旧响应先排空并丢弃，再请求最新内容，不用后来的格式解码旧响应。没有在途请求的响应忽略，规范的空失败响应不终止连接。相同检查入口直接编译正式 `Clipboard.m`，验证串行请求、取消、策略和迟到响应；私有视图与剪贴板不代替 Guest 实机验收。远端不回复时不会通过超时重发无编号请求，恢复体验与本机内容抢占仍见状态文档。

本机内容变更替换全部旧格式；空内容、不支持的类型与无效 UTF-8 发布零格式列表，WinPR 的内部格式 0 不作为 RDP 可用格式发送。通道发送失败不消费该次内容版本，后续轮询可重试；发送成功只表示交给通道，不代表 Guest 已确认或已完成粘贴。

远端请求同时绑定已观察的本机复制代次。主线程写回前复核实际 pasteboard change count；检测到本机更新便保留本机内容，丢弃旧请求的写回。客户端自身的远端写回只更新已知 change count，不增加“本机复制”代次，避免误伤后续远端复制。定时器不会将该版本自动回传到 Guest；用户再次本机复制会解除来源标记，主动粘贴远端来源的文本仍须发布并确认格式后才发送 Ctrl+V。此复核不是 macOS 跨进程原子比较写入，也不代表所有剪贴板竞争已获实机验收。

每通道只保留一个在途格式列表，等待确认期间不替换已发布的本机数据。只有规范的成功确认才允许返回格式数据；拒绝、畸形或未确认时返回空失败响应，无对应请求的确认忽略。不以等待时间推断成功；无确认的超时恢复和双向所有权切换仍需验收，详见唯一状态文档。

`freerdp-mac-edit-actions.patch` 为远程视图接入原生复制、剪切、全选及粘贴响应和菜单验证；Ctrl+C/X/A/V 会隔离已转发的 Command 等修饰键，跨设备剪贴板动作遵守策略。被禁用的 Cmd+C/X/V 即使从菜单回落到原始按键路径，也会消费对应按下/松开事件，不转发为普通字母；普通字母和 Guest 的 Ctrl 快捷键仍保留。粘贴绑定触发时的本机版本，仅在对应出站内容已确认、非空且远程视图仍持有焦点时执行一次；确认由协议线程转交主线程，通道关闭使迟到动作失效。内容变化、焦点离开或 8 秒单调时钟预算耗尽取消动作，超时不重置仍在途的无 ID 格式确认；不能用等待时长或逐字输入推断粘贴成功。当前拒绝/超时使用系统提示音，完整可访问反馈、双向所有权和 Guest 实机验收仍未完成。构建测试真实编码器、私有剪贴板与回调接线，不代表真实应用粘贴已经通过。

远端收到的文本在独立、用后释放的 Clipboard 中转换，不覆盖本机出站缓冲区；无效响应标志及缺失载荷拒绝。转换隔离不等于完整双向所有权协调，迟到响应和真实 OS 行为仍按状态文档验收。

```text
.build/app/VC Workspace.app
```

开发时可用 `VC_WORKSPACE_FREERDP_SOURCE` 与 `VC_WORKSPACE_FREERDP_BUILD_DIR` 复用本地源码和构建目录；这两个变量只影响构建，不会成为运行时依赖。

## 验证

```bash
swift test --disable-sandbox
./scripts/verify-app.sh
```

仓库根目录的 `make macos-gateway-check` 在当前 `.app` 构建后运行完整 Swift 回归及 Go TLS 网关/原生 Bridge 互操作；`make macos-check` 和 macOS CI 已串入此入口。它不安装测试 CA，不访问 PVE，只验证通道与内层 TLS 协商，不能代替真实 OS 桌面测试。未设置夹具路径的普通 `swift test` 会明确跳过互操作套件。

长传输回归单独运行 `make macos-gateway-soak-check`，覆盖同一连接内 120 MiB 往返、消费者背压和 60 秒空闲后的继续传输，约需三分钟；范围与真实桌面验收的区别见 [网关验证方法](../../docs/architecture/session-gateway.md#验证方法)。

`make macos-rdp-reactivation-check` 使用当前包内 FreeRDP 的真实 client/peer，通过匿名 socket 与内存中生成、精确校验的 TLS 证书测试 32 次分辨率重协商和光标缓存生命周期；另外验证缺失光标导致失败、保留既有错误码及主动取消。已串入 `macos-check` 和 macOS CI。此夹具没有 AppKit、OS 登录或 PVE，也不经过 Gateway，不能代替真实窗口/Guest 验收；每个进程最多运行 40 秒，不写证书文件或建立监听端口。

内置运行库为未知的接收/更新回调失败补充 `ERRCONNECT_CONNECT_UNDEFINED`，避免错误码 0 被上层当作正常断开。既有特定错误和主动取消保持原样；未知错误不进入网络自动恢复白名单。此分类修复不代表全屏断线根因已经解决，完整状态仍见 MAC-03。

验证脚本检查深度签名、所有 Mach-O 的 macOS 14 最低版本，并拒绝指向 Homebrew、MacPorts、`/usr/local`、用户目录或临时构建目录的动态库依赖和 RPATH。真实验收仍必须从 `.app` 启动，覆盖本地登录与 Keychain 恢复、桌面卡片与搜索、应用/设置/编辑/显示/连接/窗口/帮助菜单、停止桌面的启动链路、运行中桌面的直接连接、Debian 与 Windows 图像/键鼠、自适应网络、剪贴板、最小/默认/宽窗口缩放、全屏往返、关闭/隐藏/最小化后由 Dock 恢复、主动断开和显式退出清理。单元测试或不可达端点冒烟测试不能替代真实桌面验收。

可选的原生离屏渲染目录（在 `clients/macos` 下执行）：

